## Deviations from the spec (found while prototyping)

1. **B8, the glow fix, is different.**
   - **What the spec assumed:** the glow paints over the content.
   - **What prototyping showed:** `.card-glow` is already behind the content (it comes earlier in the DOM, and the content is `relative`). The real cause is a 22% accent wash under accent text, made worse by the accent button's translucent tint, which let the glow show through.
   - **The fix:**
     - the accent button's tint becomes **opaque**: `bg-[color-mix(in_srgb,var(--accent)_8%,var(--surface))]`;
     - the glow strength becomes a theme token, `--card-glow`: **22% dark, 10% light**.
   - **Measured result:** light text over the full glow is 4.73:1 and the button is 4.87:1; dark is 5.14:1 and 6.74:1.
2. **No e2e for B8.** axe can't measure contrast over the glow's gradient. A prototype e2e passed even on the old code, so it was dropped. `src/test/accent-contrast.test.ts` pins the glow and the tint from the real tokens.
3. **Shared key helpers.** `composing` and `isPaletteShortcut` live in `src/lib/palette/keys.ts`, shared by the trigger and the (lazy) palette, so the palette chunk doesn't import the trigger.
4. **E2E presses `ControlOrMeta+k`.** On macOS the shortcut is now ⌘K (B2), so Playwright's platform-aware modifier is used. CI on Linux presses Ctrl.
5. **Misconfiguration also refunds the visitor's slot** (C2/B7): a missing key is the owner's fault, not the visitor's.
6. **Coverage tests.** "Blocked Turnstile shows the alert after the wait", "waits for a fresh token after expiry" and "doesn't refund a failed human check" pass before and after. They pin existing behaviour (spec C7), not a change.

## Review Focus

1. **An abandoned challenge.** A visitor who opens Cloudflare's challenge and walks away sees "Sending…" for up to 2 minutes, then the verification alert. Reviewer: confirm the pending state clears on every exit.
2. **Keyboards without Ctrl or Meta.** On Windows the Win key (Meta) no longer opens the palette, and Ctrl+K does. iPads with keyboards count as Apple (⌘K). Pinned by `keys.test.ts`.
3. **`BUILD_TIME` exposure.** `next.config.ts`'s `env` inlines it wherever it's referenced. It's used only by the server-side sitemap, so it is harmless if it ever reached the client. Reviewer check.
4. **A Proxy matcher edge.** `apple-icon$` must still exclude the real `/apple-icon?<hash>` URL, because the query isn't part of the path. Pinned by e2e `seo.spec.ts` ("the Apple touch icon … served").

`src/lib/palette/keys.ts`:

```ts
/** Keyboard helpers shared by the palette trigger and the palette. */

/** True while an IME is composing (Safari reports keyCode 229 instead). */
export const composing = (e: { isComposing: boolean; keyCode: number }) =>
  e.isComposing || e.keyCode === 229;

/**
 * ⌘K on Apple devices, Ctrl+K elsewhere (Ctrl+K on a Mac is the system
 * "delete to end of line" in text fields). Matched by physical key too, so it
 * works on non-Latin layouts. Repeats, Shift/Alt and IME composition are
 * ignored.
 */
export function isPaletteShortcut(e: KeyboardEvent, apple: boolean): boolean {
  if (composing(e) || e.repeat || e.altKey || e.shiftKey) return false;
  const k = e.code === "KeyK" || e.key.toLowerCase() === "k";
  const mod = apple ? e.metaKey && !e.ctrlKey : e.ctrlKey && !e.metaKey;
  return k && mod;
}
```
