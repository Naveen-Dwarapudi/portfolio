# SEO, Sharing and Performance (Phase 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page gets canonical, Open Graph and Twitter metadata, plus a branded build-time share card with the owner's portrait. The site gains `sitemap.xml`, `robots.txt`, Person / WebSite / CreativeWork JSON-LD, an Apple touch icon and theme colours, all with zero client JS.

**Architecture:**
- **Pure libraries.** `src/lib/seo.ts` (metadata), `src/lib/structured-data.ts` (JSON-LD) and `src/lib/og/` (card colours and renderer) feed the route files.
- **Share images.** They use Next's `opengraph-image` and `apple-icon` file conventions with `ImageResponse`, statically generated at build time. Fonts and the portrait are read at module load.
- **Routing.** The locale Proxy passes the `/en/...` share-image URLs through, and its matcher skips `robots.txt`, `sitemap.xml` and `apple-icon`, so every new URL answers 200 with no redirect.

**Tech Stack:** Next.js 16.4 (metadata API, `next/og`, Cache Components), Vitest, Playwright, calibrated LHCI, and fonttools (one-off, to make the TTF subsets). No new npm dependencies.

**Spec:** `docs/superpowers/specs/2026-10-11-seo-perf-design.md`

**Prototype evidence:** every file below was built and verified in a throwaway worktree before the plan was written.
- **Unit tests:** 318/318.
- **E2E:** 108/108.
- **Build output:** all cards are static (`● /en/opengraph-image`, `● …/opengraph-image/[__metadata_id__]`, `○ /apple-icon`, `○ /robots.txt`, `○ /sitemap.xml`).
- **Calibrated LHCI:**
  - `/`: best LCP 2403 ms, against `main` measured the same day at 2405 ms.
  - The case study: 2172–2174 ms.
  - Script transfer unchanged within noise (144,509 B).

- **Visual check:** home and case-study cards and the 180 px icon.

## Global Constraints

- **No client JS added.** Metadata, JSON-LD and cards are server or build-time output only. **No new npm dependencies.**
- **Absolute URLs** come only from `siteUrl` (`@/lib/site-url`). Never hard-code a domain.
- **Names:** the full name "Bhavani Sankar Naveen Dwarapudi" goes on the home card and in the Person `name`. "Naveen Dwarapudi" appears in `siteName`, the card bylines and titles.
- **Confidentiality:** no client names in cards, sitemap or JSON-LD (guard tests).
- **Budgets never raised.** LCP ≤ 2500 ms (best of 3), CLS < 0.02, script ≤ 153,600 B.
- **No commits during execution.** The owner reviews and commits (skill `suggest-commit`), with no AI attribution lines.
- Branch: `feat/seo-perf`.

## Deviations from the spec (found while prototyping)

1. **Three static TTFs, not "Geist 400–500".** satori can't use variable fonts. `src/fonts/og/` holds `bricolage-grotesque-800-latin.ttf`, `geist-400-latin.ttf` and `geist-500-latin.ttf` (about 38 KB, 25 KB and 25 KB; build-time only).
2. **Fonts and the portrait are read at module load** (top-level `await`), as Next's opengraph-image docs show. Reading them inside the render failed the build's static generation under Cache Components ("used IO that was not cached"), and the cards answered 500.
3. **Share-image routing.** Cards generated under `[lang]` get `/en/...` URLs. Rather than letting the Proxy 308 them, `isShareImage(rest)` lets `/en/opengraph-image` and `/en/work/<known slug>/opengraph-image/<id>` through untouched. The matcher literal gains `apple-icon|robots\.txt$|sitemap\.xml$`.
4. **No separate `twitter-image` files.** Next emits `twitter:image` from the `opengraph-image` automatically (verified in the HTML).
5. **The portrait audit found nothing to fix.** The LCP portrait is already a **5.5 KB AVIF** at the right size on Lighthouse's mobile profile. The finding is recorded and nothing is changed.
6. **`/robots.txt` leaves the "runs through the Proxy" test list.** Phase 5's matcher test listed it as a should-proxy path; it is now a real file the Proxy must skip.
7. **Confidentiality guard.** The guard's hashed-term check moves to `src/test/confidential-terms.ts` (reused by the sitemap and JSON-LD tests), and `.ttf` joins its binary skip list.
8. **Card weight.** Cards are about 135–255 KB PNG because they embed the photo. Platforms accept 5–8 MB; the size is noted, not optimised.

## Review Focus

1. **`NEXT_PUBLIC_SITE_URL` in production.** Cards, canonicals, the sitemap and JSON-LD all use it, and a missing value throws at build on Vercel production (existing `resolveSiteUrl` behaviour). Reviewer: confirm nothing falls back to `localhost` in production.
2. **A new case study later.** It must get a card, a sitemap entry and JSON-LD with no extra wiring (`generateStaticParams` and `sitemap` read `caseStudies`). Reviewer check.
3. **Unknown-slug image URLs** (`/en/work/nope/opengraph-image/card`) must not answer 200. `isShareImage` rejects them, so they 308 and then 404. Pinned by the `isShareImage` unit test.
4. **JSON-LD injection.** Any `<` in content is escaped (`<`). Pinned by the `serializeJsonLd` test.
5. **Theme colours drifting from tokens.** Pinned by `src/lib/og/colors.test.ts`.

import type { Metadata } from "next";
import { siteUrl } from "@/lib/site-url";

/** Absolute URL on the canonical origin (NEXT_PUBLIC_SITE_URL). */
export function absoluteUrl(path: string, base: URL = siteUrl): string {
  return new URL(path, base).toString();
}

/**
 * Canonical, Open Graph and Twitter metadata for one page. The share image
 * comes from the route's opengraph-image file, which Next adds on its own.
 */
export function pageMetadata({
  title,
  description,
  path,
  type,
  siteName,
}: {
  title: string;
  description: string;
  /** Locale-free path, e.g. "/" or "/work/x". */
  path: string;
  type: "website" | "article";
  siteName: string;
}): Metadata {
  return {
    title,
    description,
    alternates: { canonical: path },
    openGraph: {
      type,
      url: path,
      title,
      description,
      siteName,
      locale: "en",
    },
    twitter: { card: "summary_large_image", title, description },
  };
}

`src/lib/structured-data.ts`:

```ts
import type { CaseStudy, HomeContent } from "@/content/types";
import { absoluteUrl } from "@/lib/seo";

const PERSON_ID = "/#person";
const WEBSITE_ID = "/#website";

type Json = Record<string, unknown>;

/** schema.org Person + WebSite for the home page. */
export function homeStructuredData(c: HomeContent, base?: URL): Json {
  const url = absoluteUrl("/", base);
  return {
    "@context": "https://schema.org",
    "@graph": [
      {
        "@type": "Person",
        "@id": absoluteUrl(PERSON_ID, base),
        name: c.footer.name,
        alternateName: c.seo.siteName,
        jobTitle: c.seo.jobTitle,
        worksFor: { "@type": "Organization", name: "Aziro Technologies" },
        url,
        email: `mailto:${c.contact.email}`,
        image: absoluteUrl("/opengraph-image", base),
        sameAs: [c.contact.linkedin.url, c.contact.github.url],
        address: {
          "@type": "PostalAddress",
          addressRegion: "Andhra Pradesh",
          addressCountry: "IN",
        },
      },
      {
        "@type": "WebSite",
        "@id": absoluteUrl(WEBSITE_ID, base),
        name: c.seo.siteName,
        url,
        inLanguage: "en",
        author: { "@id": absoluteUrl(PERSON_ID, base) },
      },
    ],
  };
}

/** schema.org CreativeWork for one case study, authored by the Person. */
export function caseStudyStructuredData(study: CaseStudy, base?: URL): Json {
  return {
    "@context": "https://schema.org",
    "@type": "CreativeWork",
    name: study.title,
    description: study.summary,
    url: absoluteUrl(`/work/${study.slug}`, base),
    about: study.kicker,
    inLanguage: "en",
    author: { "@id": absoluteUrl(PERSON_ID, base) },
  };
}

/** JSON for a <script> tag: "<" escaped so content can't close the tag. */
export function serializeJsonLd(data: Json): string {
  return JSON.stringify(data).replace(/</g, "\\u003c");
}
```

const meta = (page: Page, attr: "property" | "name", key: string) =>
  page.locator(`meta[${attr}="${key}"]`).first().getAttribute("content");

/** Width and height from a PNG's IHDR chunk. */
function pngSize(buf: Buffer) {
  expect(buf.subarray(1, 4).toString()).toBe("PNG");
  return { width: buf.readUInt32BE(16), height: buf.readUInt32BE(20) };
}

/** Fetch a site URL as the test server sees it (og URLs use NEXT_PUBLIC_SITE_URL). */
async function fetchSitePath(request: APIRequestContext, absolute: string) {
  const { pathname, search } = new URL(absolute);
  return request.get(pathname + search, { maxRedirects: 0 });
}

for (const route of ROUTES) {
  test(`${route} has canonical, Open Graph and Twitter metadata`, async ({
    page,
    request,
  }) => {
    await page.goto(route);
    const canonical = await page
      .locator('link[rel="canonical"]')
      .getAttribute("href");
    expect(new URL(canonical!).pathname).toBe(route);
    expect(await meta(page, "property", "og:title")).toBeTruthy();
    expect(await meta(page, "property", "og:description")).toBeTruthy();
    expect(await meta(page, "property", "og:url")).toBe(canonical);
    expect(await meta(page, "property", "og:type")).toBe(
      route === "/" ? "website" : "article",
    );
    expect(await meta(page, "name", "twitter:card")).toBe(
      "summary_large_image",
    );
    expect(await meta(page, "property", "og:image:alt")).toBeTruthy();

    const image = await meta(page, "property", "og:image");
    expect(image).toMatch(/^https?:\/\//);
    const res = await fetchSitePath(request, image!);
    expect(res.status(), image!).toBe(200);
    expect(res.headers()["content-type"]).toBe("image/png");
    expect(pngSize(await res.body())).toEqual({ width: 1200, height: 630 });
  });
}
