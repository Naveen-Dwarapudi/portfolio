## 1. Purpose and scope

Make every page discoverable and good-looking when shared, describe the owner to
search engines accurately, and widen the home page's LCP margin. Everything is
generated at build time at zero cost.

### Success criteria

1. **Share cards:** branded 1200×630 PNG cards for the home page and each case
   study, generated at build time.
   - **Home:** the full name, role and site host, with the owner's portrait.
   - **Case studies:** the kicker (domain only), title and "Case study · Naveen
     Dwarapudi", with a small portrait.
   - Every card has alt text.
2. **Metadata on every page:**
   - a canonical URL derived from `siteUrl`;
   - Open Graph (title, description, image, `og:site_name`, `og:locale` `en`,
     `og:type` `website` / `article`);
   - Twitter `summary_large_image`.
3. **Search files:**
   - **`/sitemap.xml`:** the home page plus six case studies, with absolute URLs
     from `siteUrl`.
   - **`/robots.txt`:** allow all, disallow `/api/`, and reference the sitemap.
   - **Hidden from search:** the resume (`X-Robots-Tag: noindex`) and the 404
     page (`robots: noindex`), as today.
4. **JSON-LD:** **`Person`** plus **`WebSite`** on the home page, and
   **`CreativeWork`** (authored by the Person) on each case study. It never names
   clients (the confidentiality guard scans it).
5. **Icons and colours:** an Apple touch icon (the ND. monogram, 180×180,
   generated at build time) and a `theme-color` per colour scheme.
6. **Direct responses:** every new URL (cards, sitemap, robots, Apple icon)
   answers **200 with no redirect**. The locale Proxy never rewrites or
   redirects them.
7. **LCP image audit:** measure the bytes of the portrait that Lighthouse's
   mobile profile fetches before LCP. If they are oversized for the rendered
   size and DPR, reduce them (`sizes` / quality), with no visible change. The
   home page's best-of-3 LCP must not get worse and should improve.
8. **Budgets unchanged:** no client JS added (metadata, JSON-LD and cards are
   server-only output). Confidentiality guard passes.

### Out of scope

- **`hreflang`** for hi/te: added when a locale publishes (i18n spec §6 runbook).
- **The `/resume` viewer page:** a candidate for phase 9.
- **Custom domain:** a future Vercel setting plus the `NEXT_PUBLIC_SITE_URL`
  change, with no code edit.

## 2. Share cards

- **Generation:** `opengraph-image.tsx` (and `twitter-image` reusing it) via
  `next/og` `ImageResponse`, statically optimized at build time (no
  request-time APIs).
  - **Home:** in the home segment.
  - **Case studies:** per slug, using `generateStaticParams`.
- **Layout (1200×630):**
  - **Background:** `--bg` dark (`#0b0d12`) with a 6px burnt-orange
    (`#FF8A3D`) bar on the left edge and a subtle grain-free radial glow.
  - **Home, left column:**
    - the name in Bricolage 800 (about 64px, wrapping to two lines);
    - "React & React Native Engineer" in Geist 500 at 30px, colour `--muted`;
    - the site host (from `siteUrl`) in Geist 400 at 24px, colour `--accent`.
  - **Home, right:** the portrait (`mypic-2.jpeg`), 360×360, with 28px rounded
    corners and a hairline border.
  - **Case study, left column:**
    - the kicker in uppercase Geist at 22px with letter spacing, colour
      `--accent`;
    - the title in Bricolage 800 (about 60px, up to three lines);
    - "Case study · Naveen Dwarapudi" in Geist at 24px, colour `--muted`.
  - **Case study, right:** a 200px round portrait.
- **Alt text** (from content):
  - **Home:** "Bhavani Sankar Naveen Dwarapudi, React & React Native Engineer".
  - **Case study:** "{title}, a case study by Naveen Dwarapudi".
- **Colours:** hex values are written directly, because `ImageResponse` can't
  read CSS custom properties. They are copied from the dark tokens in
  `globals.css`, and a unit test asserts they still match.
- **Fonts:** `ImageResponse` (satori) can't read woff2.
  - Add TTF subsets `src/fonts/og/bricolage-grotesque-800-latin.ttf` and
    `src/fonts/og/geist-400-500-latin.ttf`.
  - They are generated by the same fonttools recipe (no `--flavor`), with the
    same OFL licence. `src/fonts/README.md` is updated.
  - They are read only at build time, so they are never sent to browsers.
- **Portrait:** read from `src/images/mypic-2.jpeg` at build time and embedded
  as a data URL. `ImageResponse` scales it into the frame, and no new
  dependency is added.

## 4. Search files and JSON-LD

- **`src/app/sitemap.ts`:**
  - **Entries:** `/` with priority 1, then `/work/<slug>` at 0.8 each, read
    from `caseStudies`.
  - **`lastModified`:** a build constant, never `new Date()` in a cached path
    (Cache Components). The value comes from a `"use cache"` helper or a
    constant set at build time.
- **`src/app/robots.ts`:** `{ rules: [{ userAgent: "*", allow: "/", disallow: "/api/" }], sitemap: <abs>/sitemap.xml }`.
- **JSON-LD:** a server component, `<JsonLd data={...} />`, renders
  `<script type="application/ld+json">`. Before serialising, the JSON escapes
  `<` as `<` (an XSS-safe pattern).
  - **`Person`** (home):
    - `@id` `<abs>/#person`, `name` (the full name), `alternateName` "Naveen
      Dwarapudi";
    - `jobTitle` "React & React Native Engineer";
    - `worksFor` { Organization "Aziro Technologies" };
    - `url`, `email` (`mailto:`);
    - `image` (the absolute OG image URL);
    - `sameAs` [LinkedIn, GitHub];
    - `address` { addressRegion "Andhra Pradesh", addressCountry "IN" }.
  - **`WebSite`** (home): `@id` `<abs>/#website`, `name`, `url`, `inLanguage`
    "en", `author` → `#person`.
  - **`CreativeWork`** (case study): `name` (title), `description` (summary),
    `url`, `about` (the kicker), `author` → `#person`, `inLanguage` "en".

## 5. Proxy and routing

These metadata URLs are served at the app root, outside `[lang]`, so the Proxy
leaves them alone:
- `/sitemap.xml` and `/robots.txt`;
- `/apple-icon.png`, plus its generated variants;
- the OG and Twitter images.

**How:** the matcher literal gains exclusions for `sitemap\.xml$`,
`robots\.txt$` and `apple-icon`, plus the card image paths. The cards are
generated beneath `[lang]`, so either the Proxy passes
`/en/**/opengraph-image*` and `/en/**/twitter-image*` through unchanged, or the
image URL emitted in the metadata is made redirect-free. **The exact approach is
confirmed in the prototype**, and the outcome is pinned by e2e: every image URL
in the HTML answers 200 with `content-type: image/png` and no 3xx.

`proxy.test.ts` pins the new matcher exclusions.

## 8. Decisions log

| Decision | Choice | Why |
|---|---|---|
| Card generation | `next/og` at build time, with per-slug static params | zero runtime cost, always in sync with content |
| Portrait on cards | Yes (owner) | faces lift click-through on shared links |
| Card fonts | TTF subsets used only at build time | satori can't read woff2; never shipped to browsers |
| Metadata | One `pageMetadata` helper | consistent canonical, Open Graph and Twitter on every route |
| Structured data | Person plus WebSite (home); CreativeWork (case studies) | accurate name and profile links in search, without client names |
| hreflang | Deferred to locale publish | only English is published |
| Card fonts (final) | Three static TTFs: Bricolage 800, Geist 400, Geist 500 | satori can't use variable fonts |
| Card asset loading | Read at module load (top-level await) | reads during render are uncached IO under Cache Components |
| Share-image URLs | Proxy passes `/en/…/opengraph-image…` through (`isShareImage`) | no redirect on the og:image URL |
| Portrait audit | No change: 5.5 KB AVIF at the right size | nothing to gain; LCP is dominated by other work |
| Case-study cards (final) | Rendered on first request, then cached by Next/Vercel; the home card and Apple icon are prerendered | `generateImageMetadata` (needed for the per-title alt text) prevents prerendering; first render is about 40 ms; final review I-1 |
| CreativeWork author | Named inline (`@type` Person, `name`, `url`) as well as the `@id` | Google doesn't resolve an `@id` defined on another page |
| Card dimensions (final) | 10px accent bar; home portrait 360px (28px radius), case-study portrait 220px round; type 70/32/26 (home) and 24/64/26 (case study) | tuned for legibility at LinkedIn's preview size; recorded in phase 9 |
